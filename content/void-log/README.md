# Void log

The public text of every void a team key records (TP §3.4.7, BR-45). `scripts/team/void.ts` writes one file per void,
`<campaign address>-<UTC time>.md`, and sends `team_void_campaign` with the reason and the **SHA-256 of exactly the
file's bytes**, which the program stores in the campaign (`void_note_hash`) and the `CampaignVoided` event carries.

- **Never edit a committed record.** Its hash is on-chain; an edited file no longer matches, and anyone can check
  that (`sha256sum <file>` against the event). A correction is a new file that names the old one.
- **Commit the record with the void.** The script prints the path; the file belongs in the same day's commit.
- **A `.pending` file is a void whose answer never came.** The script writes the record as `<name>.pending`, renames
  it once the ledger confirms the void, and removes it when the program refuses. If it stays (a timeout, an RPC
  error), compare the campaign's `void_note_hash` with the SHA-256 the script printed: rename the file on a match,
  delete it otherwise. Never commit a `.pending` file.
- **What a team key may void.** Only an automatic void (a campaign `resolve_campaign` voided: missed window,
  unreadable account, stale feed), never a YES or NO (`TeamVoidNotAutomatic`, decision of 2026-10-09). The reason is
  `TeamHouseFailure` (the 10% opening fee goes back to the opener, unless nobody had entered) or `TeamOutsideCause`
  (Brot keeps it).
- **Who acted, and nothing more about a person.** The header names the acting team key, for accountability: the same
  key signs the void on-chain, where anyone can read it, and `content/powers.md` (Sprint 13) will say whose keys the
  team keys are. The text explains the cause in public terms and names no person and no private wallet owner; the
  script refuses text with an email address, an `@handle` or a URL. The record is permanent (its hash is on-chain and
  Git keeps every version), so nothing goes in that could ever need deleting.

## The public format (Sprint 12)

A void record is exactly what `scripts/team/void.ts` writes:

```text
# Void of campaign <campaign address>

- Reason: TeamHouseFailure | TeamOutsideCause
- Team key: <the acting team key>
- Written (UTC): <ISO time, e.g. 2026-10-10T18:04:05.123Z>

<the team's public text>
```

named `<campaign address>-<that time with ':' and '.' as '-'>.md`. A correction is written by hand in the same shape:

```text
# Correction of <the file name of the record it corrects>

- Team key: <the acting team key>
- Written (UTC): <ISO time>

<the team's public text>
```

The schema is `VoidLogRecord` in `packages/sdk/src/schemas/void-log.ts`; its JSON Schema is `record.schema.json`
here, generated by `bun run scripts/void-log-schema.ts` (never by hand). CI fails when the schema file is stale or
when any committed record does not parse (`tests/site/void-log.test.ts`). The site lists every record at `/record`,
newest first, and shows a void's text on its campaign page only when the file's SHA-256 equals the campaign's
`void_note_hash` on-chain. The privacy review of this record (the nine
questions of `.claude/rules/privacy-audit.md`) is in `session-log/2026-10-09-sprint-05-sdk-e-ciclo-devnet.md`.
